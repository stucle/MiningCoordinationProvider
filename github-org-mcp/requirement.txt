12a. [phát hiện lúc test push thật] "gitClone/gitFetch/gitPush trong gitops.go không hề dùng token đã resolve — chỉ 3 tool REST ở github_api.go dùng" → đây là lỗ hổng kiến trúc thật: caller (Claude) buộc phải nhúng token vào repoUrl/remote qua tool-call argument mới auth được git, mà chính permission classifier của Claude Code lại chặn mọi tool-call chứa credential-trong-URL ("Sensitive Information Leakage") — bế tắc. Fix: `gitops.go` giờ tự inject token nội bộ qua cờ global `-c http.extraHeader=Authorization: Basic <base64("x-access-token:"+token)>` chèn trước subcommand, chỉ áp dụng cho clone/fetch/push (các lệnh chạm remote); add/commit/rebase/tag không cần. Token không bao giờ nằm trong `args` truyền cho `guardCheck` nên không lộ ra alert log/stderr/tool_response. Caller giờ chỉ cần truyền `repoUrl`/`remote` thuần, không credential.
12. "reload_config ĐẶC BIỆT QUAN TRỌNG: claude lấy organName+token của chính nó truyền vào MCP; đã gọi reload thì phải ghi đè token mới; không truyền token thì reuse token cũ; đã reload thì phải restart instance tương ứng; MCP phải tự làm được" → đã hỏi lại và chốt: thêm tool mới `reload_config` (args: organName bắt buộc — khớp instance đang bind như mọi tool khác, token tùy chọn). Khi gọi: token non-empty → ghi đè accessToken cho organName đó vào env.json (cùng logic upsert như ResolveToken); token rỗng/không truyền → giữ nguyên token cũ trong env.json, không đổi gì. Sau khi ghi xong và trả response thành công, process tự os.Exit(0) — "restart" không phải do MCP tự re-exec, mà do Claude Code harness tự respawn process ở lần gọi tool kế tiếp theo đúng mcpServers entry, và process mới đọc được config đã cập nhật. MCP chỉ chịu trách nhiệm phần ghi file + exit sạch, không tự khởi động lại chính nó.
[CẬP NHẬT sau test thật] Giả định "Claude Code tự respawn ở lần gọi tool kế tiếp" SAI trên thực tế: Claude Code không tự reconnect một stdio MCP server đã chết giữa session — nó báo "failed to connect" và tool biến mất hẳn khỏi session đó cho tới khi user chủ động `/mcp` reconnect (hoặc restart session). Vậy `reload_config` hiện tại đổi trạng thái từ "có thể gọi" sang "mất tool, cần user can thiệp tay" — là một chi phí vận hành thật, không phải tự động liền mạch như kỳ vọng ban đầu.
